# 0008. Attribution from lockfile diffs and source maps

- Status: Accepted
- Date: 2026-11-03

## Context

"The bundle grew by 210 kB" is not actionable. "`moment` was added in this PR and accounts for
most of the growth" is. Existing tools show either which packages are large or which files
changed, but not why the change happened in this PR.

## Decision

- **Lockfile diff.** Parse base and head lockfiles (pnpm `pnpm-lock.yaml`, npm
  `package-lock.json` v2/v3, Yarn classic and Berry `yarn.lock`; Bun's text `bun.lock` if
  feasible) into resolved `name@version` sets per workspace. Classify each package as added,
  removed, upgraded or downgraded, and as direct or transitive (with the direct dependency that
  pulled it in, when the lockfile records the graph).
- **Source maps.** Attribute every generated byte of a bundle to its original source file using
  the source map, and map `node_modules` paths (including pnpm's `.pnpm/<name>@<version>/…`
  layout and scoped packages) to a package name. This gives minified bytes per package and per
  module for base and head.
- **Join.** Explain the bundle delta per package with the lockfile change that caused it, for
  example "added (direct)", "upgraded 4.17.20 → 4.17.21", or "no lockfile change: more of the
  package is now imported".
- **Honest units.** Per-package numbers are minified bytes from the source map. Compression does
  not split additively across packages; any per-package compressed number is labelled as an
  estimate. For Hermes, source maps describe the JS input, not the bytecode, so per-package
  numbers are JS bytes and the bytecode total is reported separately.
- **Alternatives.** Suggestions come only from `data/alternatives.json`. Each entry has a
  `source` URL. The initial data comes from the e18e
  [`module-replacements`](https://github.com/e18e/module-replacements) dataset (MIT, version
  recorded), plus entries we add by hand with a citation. A test fails if an entry has no
  source. No suggestion is generated.

## Implementation notes (milestone 3)

- Parsers turn each lockfile into one graph of importers and resolved nodes; real lockfiles of
  the same workspace from pnpm 10, npm 10, Yarn 1 and Yarn 4 are test fixtures, and all four must
  produce the same dependency list.
- Bun lockfiles are not supported yet.
- The alternatives data is generated from module-replacements 3.4.0 (`preferred`, `native` and
  `micro-utilities` manifests); suggestions link to the dataset's own guides.

## Consequences

- The comment answers "why" without an LLM.
- Lockfile formats change; parsers need fixtures per format version.

## Alternatives considered

- Package size from the npm registry (e.g. unpacked size): not what ends up in the bundle.
- Bundler stats files only: differ per bundler and do not exist for Metro.
