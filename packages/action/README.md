# usertax

**What does this pull request cost your users?**

Every pull request gets one comment with the JavaScript it adds per route, Lighthouse lab
metrics, React Native bundle and APK / AAB / IPA size, and **the dependency that caused the
change**. Web and mobile, monorepos included. No account, no API key, no data leaves your runner.

## Why teams use it

- **It says why, not just how much.** The lockfile diff of the pull request is joined with
  byte-exact source-map attribution: _"`moment` 2.30.1 was added and brought 60.1 kB"_, including
  transitive packages and the dependency that pulled them in.
- **Web and mobile in one comment.** Vite, Next.js (Turbopack and webpack), webpack and static
  sites; Expo and bare React Native bundles (JS and Hermes bytecode); APK, AAB and IPA broken down
  into code, native libraries, resources and assets.
- **Honest about noise.** Lighthouse pages are audited several times, and changes are judged
  against noise measured on GitHub-hosted runners, so an unchanged page is not reported as faster
  or slower.
- **Budgets that block.** Set limits such as "a route may not grow by more than 10 kB" and get a
  `usertax` check on the pull request that branch protection can require.
- **Sourced suggestions only.** Lighter alternatives come from the curated
  [e18e module-replacements](https://github.com/e18e/module-replacements) dataset, with a link to
  its guide. Nothing is generated by a language model.
- **Safe for public repositories.** The recommended setup never runs pull request code with a
  write token, and needs no secrets.

## Quick start

usertax measures what your workflow already builds. Build your apps **with source maps** (for
Vite: `build.sourcemap: 'hidden'` and `build.manifest: true`; for Next.js:
`productionBrowserSourceMaps: true`), then add the action.

### Private repositories: one workflow

```yaml
# .github/workflows/usertax.yml
name: usertax
on:
  pull_request:
  push:
    branches: [main] # stores the base report that pull requests are compared with
permissions:
  contents: read
  actions: read
  pull-requests: write
  statuses: write
jobs:
  usertax:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - run: npm ci && npm run build
      - id: usertax
        uses: omerozkilic/usertax-action@v0
        with:
          mode: all
      - uses: actions/upload-artifact@v7
        if: always() && steps.usertax.outputs.report
        with:
          name: ${{ steps.usertax.outputs.artifact-name }}
          path: ${{ steps.usertax.outputs.report }}
          retention-days: 90
```

### Public repositories: fork-safe, two workflows

Pull requests from forks get a read-only token, so measuring and commenting are split: the first
workflow builds the pull request without any write permission, the second runs from your default
branch and only reads the measured report, as untrusted data.

```yaml
# .github/workflows/usertax.yml
name: usertax
on:
  pull_request:
  push:
    branches: [main]
  workflow_dispatch: # run on main to recreate a missing base report
permissions:
  contents: read
jobs:
  measure:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          persist-credentials: false
      - run: npm ci && npm run build
      - id: usertax
        uses: omerozkilic/usertax-action@v0
        with:
          mode: measure
      - uses: actions/upload-artifact@v7
        with:
          name: ${{ steps.usertax.outputs.artifact-name }}
          path: ${{ steps.usertax.outputs.report }}
          retention-days: 90
```

```yaml
# .github/workflows/usertax-comment.yml
name: usertax comment
on:
  workflow_run:
    workflows: [usertax]
    types: [completed]
permissions:
  contents: read
  actions: read
  pull-requests: write
  statuses: write
jobs:
  comment:
    if: github.event.workflow_run.event == 'pull_request' && github.event.workflow_run.conclusion == 'success'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7 # your default branch: your trusted configuration
      - uses: actions/download-artifact@v8
        with:
          name: usertax-head
          run-id: ${{ github.event.workflow_run.id }}
          github-token: ${{ github.token }}
          path: .usertax-head
      - uses: omerozkilic/usertax-action@v0
        with:
          mode: comment
          head-report: .usertax-head/usertax-report.json
```

Until the workflow has run once on `main`, pull requests show head values only; after that,
every pull request is compared with the report of its merge base (or the nearest earlier one). Pin the actions by commit SHA
if your policy requires it.

## What you get on each pull request

- **One comment**, updated in place on every push: changed metrics first, unchanged ones folded
  away, then the packages that changed and why, alternatives, the largest file and archive
  changes, and the budget results.
- **A `usertax` check** (commit status) with the budget result, linking to the comment.
- **The same report in the job summary**, and the full JSON report as an artifact.

## Configuration (optional)

Without configuration, usertax finds the apps of your workspace (pnpm, npm or Yarn workspaces, or
a single package) and measures every app that is built. Add `usertax.config.json` at the
repository root for budgets, Lighthouse pages or mobile builds:

```json
{
  "apps": [
    { "path": "apps/web", "lighthouse": { "pages": ["/", "/pricing"] } },
    {
      "path": "apps/mobile",
      "framework": "react-native",
      "bundles": [{ "platform": "android", "file": "dist/index.android.bundle" }],
      "archives": [{ "file": "android/app/build/outputs/apk/release/app-release.apk" }]
    }
  ],
  "budgets": [
    { "metric": "route[*].js.gzip", "maxIncrease": "10 kB" },
    { "metric": "archive[*].file", "maxIncreasePercent": 2, "level": "warn" }
  ]
}
```

Lighthouse needs `lighthouse` and `chrome-launcher` as dev dependencies of the measured project.
All fields, metric ids and budget rules:
[configuration](https://github.com/omerozkilic/usertax/blob/main/docs/configuration.md) ·
[metrics and budgets](https://github.com/omerozkilic/usertax/blob/main/docs/metrics.md).

## Inputs

| Input               | Default               | Description                                                                               |
| ------------------- | --------------------- | ----------------------------------------------------------------------------------------- |
| `mode`              | `measure`             | `measure` (write the report), `comment` (compare and comment) or `all` (both in one job). |
| `working-directory` | `.`                   | Repository root to measure.                                                               |
| `config`            | `usertax.config.*`    | Configuration file, relative to the working directory.                                    |
| `report`            | `usertax-report.json` | Where `measure` writes the report.                                                        |
| `head-report`       | –                     | `comment`: the head report downloaded from the measure workflow.                          |
| `github-token`      | `github.token`        | Needs `actions: read`, `pull-requests: write` and `statuses: write` to comment.           |
| `fail-on-budget`    | `true`                | Fail the step and the `usertax` check when a budget fails; `false` only reports.          |
| `commit-status`     | `true`                | Set the `usertax` commit status on the pull request head.                                 |

## Outputs

| Output          | Description                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `report`        | Absolute path of the report written by `measure`.                                              |
| `artifact-name` | Name to upload it under: `usertax-base-<sha>` on the default branch, otherwise `usertax-head`. |
| `comment-url`   | URL of the pull request comment.                                                               |
| `status`        | Budget result: `pass`, `warn` or `fail`.                                                       |

## FAQ

**Does it build my app?** No. Build it as you do today; usertax reads the build output, the source
maps and the lockfile. Measuring needs no network access; only the comment step talks to the
GitHub API.

**Does it send data anywhere?** No. Everything runs on your runner; there is no service, account or
API key.

**Is there an AI summary?** No. The comment is deterministic: the same builds give the same report.
For coding agents, the CLI includes an MCP server (`npx @usertax/cli mcp`) that returns the same numbers.

**Can I use it outside GitHub Actions?** Yes, with the CLI:
[`npx @usertax/cli`](https://www.npmjs.com/package/@usertax/cli) on any CI or on your machine.
